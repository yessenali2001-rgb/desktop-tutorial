# Установка: Google Таблица как база данных

Схема: **сайт** (папка `docs/`) ↔ **скрипт Apps Script** (`Code.gs`) ↔ **таблица-база**.

- Таблица остаётся закрытой. Читает и пишет в неё только скрипт.
- Родители открывают сайт без пароля и видят только имя и класс участников.
- Организаторы входят с паролем. Главный организатор правит всё, остальные только свой вид спорта.
- Контакты родителей видны только организаторам.

Таблица-база: «Достық спартакиадасы: база данных» (вкладки: Настройки, Расписание, Арены, Участники, Матчи).

## Шаги

1. Откройте таблицу-базу → **Расширения → Apps Script**.
2. Удалите всё в файле `Code.gs` и вставьте код из `apps-script/Code.gs`. Нажмите «Сохранить».
3. Слева откройте **Настройки проекта** (шестерёнка) → **Свойства скрипта** → «Добавить свойство». Создайте четыре свойства, значения придумайте сами (не короче 8 символов):

   | Свойство | Кто входит |
   |---|---|
   | `ORGANIZER_PASSWORD` | главный организатор (логин `organizer`) |
   | `ORG_VOLLEYBALL_PASSWORD` | волейбол әкелер и аналар (логин `org_volleyball`) |
   | `ORG_TENNIS_PASSWORD` | настольный теннис (логин `org_tennis`) |
   | `ORG_CHESS_PASSWORD` | шахматы (логин `org_chess`) |

   Если свойство не задано, вход под этим логином запрещён.
4. **Развернуть → Новое развёртывание** → тип «Веб-приложение»:
   - «Выполнять от имени»: **Я**;
   - «У кого есть доступ»: **Все**.

   Google попросит разрешить доступ к таблице: разрешите (может появиться «Приложение не проверено», нажмите «Дополнительно» → «Перейти»).
5. Скопируйте **URL веб-приложения** (заканчивается на `/exec`) и впишите его в `docs/config.js` в поле `APPS_URL`.
6. Выложите папку `docs/` в интернет (GitHub Pages: Settings → Pages → ветка и папка `/docs`).

После правки `Code.gs` нужно снова сделать **Развернуть → Управление развёртываниями → изменить → Новая версия**, иначе сайт будет работать со старым кодом.

## Лимиты

Публичные данные кэшируются на 2 минуты и сбрасываются при каждом сохранении организатора. Страница родителя опрашивает скрипт раз в 30 секунд, и только пока вкладка открыта. Для нескольких сотен родителей этого хватает.

## Проверка без Google

`node apps-script/test.js` проверяет логику скрипта на имитации таблицы: вход, права по видам спорта, чтение без контактов родителей, кэш.

## Несколько организаторов под одним логином

Сайт отправляет в таблицу не весь вид спорта, а только то, что изменил именно этот организатор
(`patches`: изменённые матчи, участники, названия арен). Скрипт сливает правки с актуальными данными
под блокировкой, поэтому двое могут одновременно вводить счёт на разных аренах. Плей-офф создаётся
с фиксированными id (`po-SF1`, `po-SF2`, `po-F`, `po-B`), повторное нажатие не создаёт дубли.
Если развёрнут старый скрипт (`ping` без `features: ["patch"]`), сайт сохраняет вид спорта целиком.
